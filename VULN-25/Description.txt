Title: Missing Project-Level Authorization on SQL Web-Terminal & PD Dashboard Proxy

Weakness: Improper Access Control - Generic (CWE-284)

Asset in Scope: tidbcloud.com

Description:
Description
The SQL Web Terminal proxy and PD Dashboard proxy only enforce Organization membership. They do not check for Project-level role binding.
A user who is only org:member (with zero Project roles on the target project) can:

Access the interactive SQL login shell of a cluster that is completely hidden from them in the console.
Receive internal Kubernetes service hostnames and cluster DNS information via the PD Dashboard error response.

All normal console APIs correctly deny this user with permission denied.

Remediation
Enforce the same Project-scope authorization check used by the console APIs on both proxy endpoints (/terminal/ and /pd/dashboard/).
Additionally, avoid returning raw upstream connection errors that contain internal hostnames and DNS addresses.

Impact:
Impact

An organization member with no project permissions can reach the interactive SQL login surface of any cluster inside the organization.
Internal Kubernetes service hostnames and DNS information are disclosed.
The database password gate remains effective (no SQL execution was possible), so the impact is limited to unauthorized access to the login interface + topology disclosure.
