Title: Status API accepts unauthenticated state-changing POSTs (runtime GOGC write, DDL owner resignation)

Weakness: Missing Authentication for Critical Function (CWE-306)

Asset in Scope: TiDB product, such as TiKV, TiDB, TiFlash, PD

Description:
The same unauthenticated HTTP status API that serves monitoring pages also registers write endpoints: POST /debug/gogc changes the Go garbage-collection target of the running process, and POST /ddl/owner/resign forces the DDL owner role of the node to resign. Both are operational/administrative actions that a database normally reserves for operators.

Both were exercised anonymously against the pinned build: the GOGC endpoint accepted POST 42 with HTTP 200 (and a later POST 100 was observed to change the reported value from 500 to 100), and /ddl/owner/resign returned HTTP 200 'success!' with no credentials. Measured impact in the lab was limited: TiDB's internal GC tuner overwrote the injected 42 back to 500 before the next read, so a persistent sabotage value was not demonstrated, and the DDL owner re-election recovers on its own. The defect is that these state-changing operations require no authentication at all.

AFFECTED PRODUCT
- Product: TiDB (tidb-server)
- Component: HTTP status API, debug/write endpoints
- Version tested: v26.3.10, commit 6b4c9f9dce2118aca580a16ef49bd791f4e12b3a
- Environment: single-node local lab (own test data), status API on port 10180

VULNERABILITY DETAILS
- Class: Missing Authentication for Critical Function (CWE-306) on state-changing management endpoints
- Required privileges: none — plain HTTP POST, no credentials
- Entry point: POST /debug/gogc (body: integer), POST /ddl/owner/resign
- Trust boundary crossed: unauthenticated network peer -> server runtime / DDL ownership state
- Root cause: the status router registers these handlers with no authentication or authorization wrapper — the /debug/gogc POST branch calls util.SetGOGC: https://github.com/pingcap/tidb/blob/6b4c9f9dce2118aca580a16ef49bd791f4e12b3a/pkg/server/http_status.go#L417 ; /ddl/owner/resign: https://github.com/pingcap/tidb/blob/6b4c9f9dce2118aca580a16ef49bd791f4e12b3a/pkg/server/http_status.go#L249
- The GOGC write competes with TiDB's internal GC tuner (https://github.com/pingcap/tidb/blob/6b4c9f9dce2118aca580a16ef49bd791f4e12b3a/pkg/util/gctuner/tuner.go), which adjusts GOGC dynamically; this limits the demonstrated persistence of the write but does not gate the endpoint itself.

REPRODUCTION STEPS
1. curl http://<host>:10080/debug/gogc — read current value (observed 500)
2. curl -X POST -d '42' http://<host>:10080/debug/gogc — HTTP 200, empty body
3. curl http://<host>:10080/debug/gogc — read back (observed 500; internal tuner override). Then curl -X POST -d '100' and read back — observed 100
4. curl -X POST http://<host>:10080/ddl/owner/resign — observed 'success!', HTTP 200

BASELINE BEHAVIOR
Administrative actions of this kind (GC tuning, DDL ownership) require operator credentials over SQL (SYSTEM_VARIABLES_ADMIN / DDL-related privileges). The status API applies no such gate.

OBSERVED RESULT
POST /ddl/owner/resign  -> 'success!' [HTTP 200]
POST /debug/gogc (42)   -> [HTTP 200]
GET  /debug/gogc        -> 500 (value written by tuner; injected 42 not persisted)
POST /debug/gogc (100)  -> [HTTP 200]
GET  /debug/gogc        -> 100

NEGATIVE CONTROL
POST /upgrade/pause on the same API is rejected with 'wrong operation:pause' [HTTP 400] — input validation exists on some endpoints — while the two exploited endpoints perform their action for any anonymous caller. An additional honest limit: the injected GOGC 42 did not persist across the internal tuner cycle; only the later write to 100 was observed to stick.

Impact:
Any network peer can trigger operational actions on a TiDB node without credentials: force a DDL owner resignation (verified: re-election recovers; a transient DDL stall is the effect on the same node) and write runtime GC parameters (verified accepted; persistence is governed by the internal GC tuner). Demonstrated availability effect was transient — no deterministic outage is claimed from these two endpoints.

Severity per program rating: Low ('minor unauthorized operations' / exposed debug pages without meaningful impact); reported at the Low/Medium boundary because persistent sabotage was not demonstrated.

Fix guidance: require an operator credential (or bind write endpoints to loopback) for /debug/gogc, /ddl/owner/resign, /ingest/*, and similar state-changing status endpoints; split read-only diagnostics from write endpoints at the router level so a single middleware can enforce authentication for all mutating routes.
